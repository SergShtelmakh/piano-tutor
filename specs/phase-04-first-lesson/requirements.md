# Requirements — First lesson: play the right notes

## Context

Roadmap Phase 4: the core promise of the product, end to end. Phases 1–3 built a free-play piano with one note pipeline (`src/input/noteBus.ts`) fed by MIDI, the computer keyboard, and the on-screen piano, and deployed it over HTTPS (GitHub Pages as production, Cloudflare for branch previews). This phase adds the first lesson: the app draws a target note **on a music staff**, the learner reads it and plays the matching key, every key press is judged as right or wrong, and the lesson ends with a summary.

The lesson is a **note-reading drill with a random order**: every start gives a new sequence, so the learner has to read each note instead of remembering a pattern.

The lesson judge is pure logic that receives `noteon` events from the bus, so it works with every input source. The translations module gets interpolation and plural forms, deferred from Phase 1, because the summary needs "3 mistakes" and "85 % accuracy".

**Changed after the first review:** (1) the target is shown as a note on a grand staff (treble and bass clefs), not as a highlighted key or a note name. This pulls a minimal sheet-music view out of the backlog; it covers single white-key notes only. (2) The note order is random, not the fixed C major scale. (3) The note pool starts at B3 so both clefs are used, which needs one more computer-keyboard key and one more key on the on-screen piano.

The clarifying questions and their answers are in the **Decisions** table below.

## Functional requirements

**Navigation**

- **FR-1** The start screen must offer two modes: **Free play** (the current screen) and **Lesson**. The mode is kept in app state (no router, no URL change). Free play is the default on load. The language selector, volume, MIDI status, and build footer stay available in both modes.

**Lesson model and judge (pure)**

- **FR-2** A lesson is plain data: an id, a title key, the base octave it is played in, and an ordered list of steps. Each step is a set of one or more MIDI note numbers, so chords are possible in the model, though the first lesson uses single notes only. Lessons live in a pure module with no React, DOM, or audio imports.
- **FR-3** The judge must take the lesson state and a `NoteEvent` and return the new state and an outcome (`right`, `wrong`, `ignored`). Rules:
  - Only `noteon` is judged; `noteoff` and `sustain` are ignored.
  - A note is right if it is in the current step and not yet played in that step. The step is complete when all its notes have been played; then the lesson moves to the next step.
  - Any other note is wrong: the mistake count goes up by one, and the target does not change (the learner must still play the right note).
  - Pitch must match exactly (C4 is not C3 or C5).
  - Repeating a note that is already played in the current step (only possible in chords) is ignored.
  - After the last step the lesson is finished, and further notes are ignored.
- **FR-4** Accuracy is `correct / (correct + mistakes)`, where `correct` counts right notes. It is shown as a whole percentage, formatted for the current language. A lesson with no mistakes is 100 %.

**First lesson: random note reading**

- **FR-5** The first lesson is **"Note reading"**: 20 steps, each one note, drawn at random from the white keys **B3 C4 D4 E4 F4 G4 A4 B4 C5** (9 notes). The same note never comes twice in a row. The sequence is generated by a pure function that takes a random-number source (`() => number` in `[0, 1)`) as a parameter, so tests can pass a fixed one; the app passes `Math.random`. A **new sequence** is generated every time the lesson starts, on **Restart**, and on **Play again**. The lesson's base octave is 4.

**Keys for B3 (input range)**

- **FR-6** The computer keyboard gains one more white key: the physical `ShiftLeft` key plays the **B just below the base C** (B3 when `A` plays C4). It follows the octave shift (`Z` / `X`) like every other key. The on-screen piano gains that key too, so it shows one white key more on the left (a B before the base C, up to the C two octaves above the base C). This applies in free play as well as in lessons. Key labels on the piano show the new key's computer-key label (`⇧` when the layout map has no label for it). Pressing `ShiftLeft` while typing in a form control must not play a note (existing rule for form controls).

**Music staff (pure position logic + SVG view)**

- **FR-7** The lesson screen must draw a **grand staff**: a treble staff and a bass staff, each with its clef, joined by a bracket or a left barline. The current target is drawn as a **whole note** (an open notehead, no stem) at the correct height:
  - notes from C4 up are placed on the treble staff, lower notes on the bass staff (in this lesson only B3 is on the bass staff);
  - C4 sits on a **ledger line** between the two staves; notes further out get the ledger lines they need;
  - only white-key notes are supported in this phase (no sharps, flats, or key signatures). The position function reports an error for a black key instead of drawing it in the wrong place.
  - When the step is complete, the next target appears on the staff. Only the current target is drawn.
- **FR-8** The position logic (note → clef, line / space index, ledger lines) is pure, in `src/core/`, and unit-tested: C4 (one ledger line, treble), D4 and E4 (no ledger lines; E4 on the bottom treble line), C5, B3 (bass, no ledger line), A3 (top bass line), and a black key is rejected. The SVG component only turns these numbers into coordinates.

**Lesson screen**

- **FR-9** The lesson screen must show:
  - the lesson title and a one-line instruction, "Play the note shown on the staff" (translated);
  - the staff from FR-7, with an accessible label that names the target note with `i18n/noteNames.ts` (for screen readers only; the name is **not** shown on screen);
  - progress ("Step 3 of 20");
  - counters for correct notes and mistakes, with correct plural forms;
  - the on-screen piano. The target key is **not** highlighted. The piano keeps its normal key labels from Phase 2.
- **FR-10** Feedback: on a right note the played piano key and the notehead on the staff flash **green**; on a wrong note the played key and the notehead flash **red**. The flash lasts about 300 ms and does not delay the sound or the next judgement. Held keys stay lit as in free play. Green, red, and held differ from each other, and the meaning is not given by colour alone (the counters change).
- **FR-11** The lesson must work with every input source: MIDI keyboard, computer keyboard, and on-screen piano (touch and mouse), all through the note bus. Every note of the pool (B3–C5) is reachable with each of them without shifting the octave. Sound keeps playing as in free play.
- **FR-12** The lesson screen must have **Restart** (a new random sequence, counters reset) and **Back to free play** buttons. Leaving the lesson restores the base octave that was active before it started.

**Summary**

- **FR-13** When the last step is complete, a summary replaces the lesson: "Lesson complete", the accuracy (FR-4), the number of correct notes and of mistakes (plural forms), and two buttons: **Play again** (a new random sequence) and **Back to free play**. Notes played on the summary screen make sound but are not judged.

**Translations**

- **FR-14** The translations module must support interpolation (`{name}` placeholders, e.g. `Target note: {note}`) and plural forms chosen with `Intl.PluralRules` for the current locale (`en`/`de`/`fr`: one / other; `uk`: one / few / many / other). A missing plural form falls back to `other`; a missing key falls back to English as today. This logic is pure and unit-tested, including Ukrainian 1 / 2 / 5 / 11 / 21 / 22 / 25.
- **FR-15** Every new string exists in `en`, `uk`, `de`, `fr`.

## Non-functional requirements

- User-facing text goes through the translations module (English default; add keys for `uk`, `de`, `fr` too).
- Works with the on-screen and computer keyboard (no MIDI device required).
- No perceptible added input latency: the judge runs synchronously on the bus event, the synth is unaffected.
- Pure core (`src/core/`) holds the lesson model, the judge, the accuracy calculation, the sequence generator, the staff position logic, and the lesson data; React components only render state and forward events.
- The staff is inline SVG that scales with the screen width (readable at 360 px, no image files, no notation library).
- The staff and the clefs must render on desktop Chrome and on Android Chrome.
- No new runtime dependencies.
- Layout works at 360 px width (phone), including the extra piano key.

## Out of scope

- Saving progress, stars, XP, streaks, a lesson list (Phase 5).
- More lessons, chords in a lesson, both hands, unlock order, choosing the note pool or the length (Phase 6).
- Adaptive practice (repeating notes the learner missed).
- Sharps, flats, key signatures, other note lengths, rests, stems, beams, and time signatures.
- A full sheet-music engine, playing along with a score, a falling-notes view (backlog).
- Timing / rhythm, tempo, metronome.
- Hints after repeated mistakes (for example highlighting the target key), sound effects for right / wrong.
- A setting to hide the key labels on the piano.
- A router or URLs per screen.

## Decisions

| Question                      | Decision                                                                                | Reason                                                                                                       |
| ----------------------------- | --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| Content of the first lesson   | A random note-reading drill (20 single-note steps); the model also allows chords        | The learner must read each note instead of remembering an order; chords stay possible later.                 |
| Note pool                     | White keys B3–C5 (9 notes)                                                              | Uses both clefs (B3 is on the bass staff) and stays within about one octave.                                 |
| Lesson length                 | 20 notes                                                                                | Enough for a fair accuracy figure, still about two minutes.                                                  |
| Repeated notes                | The same note never comes twice in a row                                                | A new note always needs reading.                                                                             |
| When a new order is generated | On every start, Restart, and Play again                                                 | The order cannot be memorised.                                                                               |
| Randomness                    | The generator takes a random source as a parameter; the app passes `Math.random`        | Keeps the core pure and the tests deterministic.                                                             |
| Reaching B3 from the computer | `ShiftLeft` plays the B below the base C; the on-screen piano shows that key too        | Every note of the lesson is reachable from every source without shifting the octave.                         |
| What happens on a wrong note  | Count a mistake, flash red, wait for the right note                                     | Learners must find the right key; accuracy = correct / (correct + mistakes).                                 |
| Octave strictness             | Exact pitch; the lesson sets the base octave so the keys line up                        | Teaches real key positions.                                                                                  |
| How to reach the lesson       | Two mode buttons, Free play and Lesson, in app state                                    | Smallest navigation that works; Phase 5 replaces it with a lesson list.                                      |
| Plural rules                  | `Intl.PluralRules` with per-form strings, fallback to `other`                           | Ukrainian needs one / few / many; no library needed.                                                         |
| How the target is shown       | A note on a music staff, not a key highlight or a name                                  | The product is about learning to read notes and find them on the keyboard.                                   |
| Notes on the staff            | Only the current note                                                                   | Keeps the screen simple; the learner reads one note at a time.                                               |
| Clefs                         | Grand staff: treble and bass, with C4 on a ledger line between them                     | Matches how piano music is written.                                                                          |
| Key highlight and note name   | Neither is shown; the staff is the only hint (an invisible label for screen readers)    | Real note reading. Key labels on the piano stay as they are.                                                 |
| Clef drawing                  | SVG paths for both clefs, taken from the Bravura font (OFL), no font needed at run time | Renders the same on every device; Unicode music symbols depend on system fonts and were misplaced in a test. |
